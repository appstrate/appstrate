# Upgrading production from beta.68 to beta.70

The beta.69 tag stopped before CLI signing. Beta.70 ships its application and migrations with the native Apple Silicon build moved to macOS 15.

Use the [release runbook](https://github.com/appstrate/docs/blob/main/deployment/RELEASE_RUNBOOK.md) maintenance procedure with the application stopped. The two binaries cannot safely serve traffic against the same upgraded schema. The [migration reference](../../scripts/migration/README.md) gives the commands, prerequisites and expected output for each script.

## Prepare the release

1. Record the reviewed commit and verify its workflows, including PostgreSQL 16, Docker and browser tests. Run the Docker smoke check on a Docker host. Check the assembled OpenAPI with the deployed modules enabled against beta.68, including the chat routes. The [client migration notes](../../CHANGELOG.md#client-upgrade-from-beta68) cover paths, query filters and skill synchronization.
2. Publish `afps-shared@0.14.0`, confirm the tarball resolves from npm, then publish `core@17.0.0`. Update the external consumer `connect-helper` to the published major and refresh the export baseline using the published tarball. Verify the candidate CLI, GitHub Action and sync plugin against the candidate API. Follow the [core publication procedure](RELEASING_CORE.md).
3. Rehearse the steps below on a consistent restore of beta.68. Use an isolated network, fresh credentials, no production Redis or Docker socket, and no external deliveries. Record restore, migration, and validation durations. Work backwards from the end of the maintenance window to reserve enough time for the measured restore, beta.68 startup and acceptance checks. Run `0050-report-narrowing-overrides.ts` before the window and review every affected schedule with its owner. Verify model IDs with `bun run verify:system-models` under the deployment's module and model configuration.
4. Once the rehearsal passes, build the platform, Pi and sidecar from the same release revision. For Firecracker, verify the runner and guest artifacts for that release.

### Prepare Coolify billing

Record the application's active version, full `MODULES` list, and any explicit reconciliation overrides in the private deployment log. Keep beta.68 restartable until the writers have stopped. In the candidate configuration, replace the single `@appstrate/module-ee` entry with `@appstrate/module-billing` and retain every other entry. Move explicit `EE_RECONCILIATION_` values to the same suffix under `BILLING_RECONCILIATION_`. The suffixes are `INTERVAL_SECONDS`, `BATCH_SIZE`, `REPLAY_WINDOW`, and `MAX_GAP_SECONDS`. Keep the four Stripe variables and existing Redis configuration. Record the billing journal count, seven `ee_*` tables and `ee_billing_cursor` before starting workers. The [billing module guide](../../packages/module-billing/README.md) documents the persisted identities.

## Maintenance window

This window ends at beta.70 (core journal 110). To upgrade beta.68 directly to a release that includes core migration 0113, stop after step 2 and continue with [Upgrading through core migration 0113](UPGRADE_0113.md).

1. Drain runs and stop the application, workers and other writers. Record one UTC timestamp for `0053 --before`. Use dump and restore clients matching PostgreSQL’s major version and verify a strict restore into an empty database. Back up PostgreSQL, both package buckets (`agent-packages` and `library-packages`), and any logos needed by 0049 at the same point.
2. Run **0054 before Drizzle**. Dry-run with `--signing-dir DIR`; resolve every `UNFOLDED` line, including missing archives and publisher signatures. The reviewed dry-run must show zero unresolved entries before `--apply`. Preserve the signing directory across retries.
3. Run the release's migrate service for core journal entries 0097–0109. On an unmodified beta.68 journal, the count goes from 97 to 110. Verify that the connection reference in `connection_calls` is nullable after 0109. Apply 0048, then 0049 on instances that previously served 0097, 0051, and 0053 with the recorded timestamp. Run 0047 and 0052 in the window. Compare placement counts, manifests, stored integrity, dependency indexes and run-read rows with the rehearsal. Re-run the idempotent scripts.
4. With writers still stopped, run `bun scripts/migration/0055-chat-file-read-receipts.ts`, repeat with `--apply`, then repeat the dry run. Require zero messages left to rewrite before reopening chat. Measure peak memory and elapsed time on the copy, as this script reads stored message content.
5. Save the candidate version and billing configuration together in Coolify before deploying. Boot with `APPSTRATE_VERSION=1.0.0-beta.70` and `MIGRATIONS_ON_BOOT=verify`. Inspect Coolify's rendered Compose, readiness, runtime revisions and scheduler. Confirm the `billing` module loads against the existing `drizzle.ee_migrations` journal and cursor. Run a signed local integration, verify its output and exercise the sidecar with the runbook's network canary. Check A, B and All spaces, run acknowledgements, chat history, and local skill sync. Reopen writes and schedules after acceptance. Verify the installer and CLI npm channels separately.

## Roll back

After the first storage or database write, stop every writer. If traffic has reopened, preserve and reconcile subsequent writes before restoring. Restore PostgreSQL into an empty database, **both package buckets** and the logo objects touched by 0049 to the same backup point. Compare the schema journal, row counts, billing cursor and object inventory with the backup. Restore the beta.68 images, the recorded `MODULES` list with `@appstrate/module-ee`, and the original reconciliation variables before starting beta.68. Check readiness, read a signed archive under the original trust policy, and run an agent and a schedule before reopening traffic. Record the backup identifiers, timings, test results and promoted channels in the deployment log.
