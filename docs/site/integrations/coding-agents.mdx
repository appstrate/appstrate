If you are the platform or internal-dev engineer rolling out Appstrate inside a company, a coding agent is your fastest path. Connect [Claude Code](https://docs.claude.com/en/docs/claude-code), [Cursor](https://cursor.com/docs/skills), [Antigravity](https://antigravity.google/docs/skills) or any [AGENTS.md-aware](https://github.com/numman-ali/openskills) host, and delegate the configuration work to an agent that already knows Appstrate: authoring agents, wiring integrations, rotating keys, testing end-user impersonation, publishing AFPS packages.

Instead of opening the dashboard, reading the docs and hand-typing `curl` or `appstrate api`, you describe what you want (_"connect Gmail and create an agent that summarizes new emails every morning"_) and the coding agent executes it against your active profile.

This page is the **why and when**. For the **how** of the skill (install, targets, flags, update), see [Using Appstrate / Skill](/docs/using-appstrate/skill).

## Three ways to connect

| Way             | What the coding agent gets                                                                                                                                                                                | Setup                                                         |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| **Agent Skill** | The conventions: manifest shapes, AFPS packaging, CLI recipes, the traps. It acts through the `appstrate` CLI.                                                                                            | One install command, see [Skill](/docs/using-appstrate/skill) |
| **CLI**         | `appstrate api` for any REST call, plus commands to run agents and edit packages (`appstrate packages pull`, `push`, `publish`). Uses your named profiles.                                                | [CLI](/docs/using-appstrate/cli)                              |
| **MCP**         | The platform as an MCP server: `search_operations`, `describe_operation` and `invoke_operation` over the whole API, plus `run_and_wait`. No CLI needed, and the key's permissions decide what is visible. | `claude mcp add --transport http ...`, see below              |

They combine. The skill is the knowledge, the CLI or MCP is the hands.

### Connect over MCP

Each organization has one MCP endpoint, `/api/mcp/o/<orgId>`. With an API key that holds `mcp:read` and `mcp:invoke`:

```bash
claude mcp add --transport http appstrate-acme https://appstrate.yourcompany.com/api/mcp/o/<orgId> \
  --header "Authorization: Bearer apst_your_key"
```

Clients that support browser OAuth can skip the key and log in instead. The dashboard shows the exact command for each organization. Details: [Connecting MCP clients](https://github.com/appstrate/appstrate/blob/main/docs/guides/connecting-mcp-clients.md).

## Why this pattern

- **Faster config loops.** Authoring an agent, connecting its integrations and adding a webhook normally takes many clicks or precise API calls. A coding agent does it in one prompt, with the manifest conventions in hand.
- **Multi-instance workflows.** The CLI uses named profiles (`dev`, `staging`, `prod`). The agent can diff a configuration between them or replay a production change on staging first.
- **End-user impersonation checks.** Ask the agent to validate that a flow works for three end-users. It loops through them with the `Appstrate-User` header.
- **Less context switching.** Ship an internal feature that uses Appstrate from the same chat where you wrote the code.
- **AFPS packaging.** The agent knows the manifest shape, dependencies, semver and the publish flow, including [custom integrations](/docs/integrations/custom-providers).

## Use cases that land well

- _"Create an agent called `email-triage` that reads my Gmail inbox and posts a summary to Slack. Use the `@appstrate/gmail-mcp` and `@appstrate/slack` integrations and select only the tools it needs."_
- _"Rotate the API key named `ci-deploy`: create the new one, check it works, then revoke the old one."_
- _"Write a custom integration for our internal API at `https://api.acme.com`, with an API key in the `Authorization` header, import it, and add it to the `reporting` agent."_
- _"Pack my local `./my-skill` folder as an AFPS and publish it under `@acme/my-skill`."_
- _"List every agent whose runs failed more than 10% of the time this week and show the last failed run's logs."_
- _"Diff my `dev` profile's agent list with `prod` and tell me what is missing on prod."_

The agent reads the skill's instructions and references on demand, picks the right call, runs it and reports back. If something fails, it should stop and show the error instead of retrying blindly. Review what it is about to do on a production profile, as you would a colleague's change.
