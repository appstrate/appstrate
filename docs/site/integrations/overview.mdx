---
title: Overview
description: How Appstrate connects to third-party services and model providers, and how personal agents and coding agents connect to Appstrate.
---

Appstrate connects in two directions.

**Inbound, plug things into Appstrate.** _Integrations_ (Gmail, Slack, Notion, and 64 others) give agents access to third-party services without exposing credentials: each is an AFPS package, connected per user or end-user, called through the sidecar. _Model providers_ supply the LLM that runs the agent: you bring an API key for one of the supported vendors or a custom OpenAI or Anthropic compatible endpoint, or an operator enables a Claude or ChatGPT subscription provider.

**Outbound, plug Appstrate into other systems.** A personal agent running on your own machine can use Appstrate as an execution backend: it reasons locally, then launches runs through the REST API or MCP when you need multi-tenant execution, credential-hidden tool calls or parallel runs. Coding agents such as Claude Code can drive Appstrate the same way.

None of the outbound patterns is shipped as an SDK. They are **patterns over the REST API and the MCP endpoint**, documented below so you know what to build.
