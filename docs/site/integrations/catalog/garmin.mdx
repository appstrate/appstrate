## Overview

Garmin offers no public API for individuals. Appstrate ships two integrations that read what Garmin's own apps read, through undocumented endpoints that may change without notice. Automated reading may also fall outside Garmin's terms of use, so check them before you rely on either.

| Integration                   | Source     | What the agent reads                                                                                                             |
| ----------------------------- | ---------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `@appstrate/garmin-connect`   | `api_call` | One member's activities (summary, GPS track, laps, heart-rate zones, weather, GPX and FIT files), daily health data and profile. |
| `@appstrate/garmin-livetrack` | `api_call` | The last position and the LiveTrack sessions behind a public personal LiveTrack link.                                            |

## Garmin Connect

The integration uses the public client of the Garmin Connect mobile app, so there is nothing to create at Garmin. Two steps remain, one for the administrator and one for each member.

<Steps>
<Step>

**Administrator, once.** Register a public OAuth client (no secret) whose client ID is `GARMIN_CONNECT_MOBILE_ANDROID_DI_2025Q2`. Without one, connecting is refused with a 403.

```bash
appstrate api POST /api/integrations/@appstrate/garmin-connect/auths/primary/oauth-clients -d '{
  "client_id": "GARMIN_CONNECT_MOBILE_ANDROID_DI_2025Q2",
  "token_endpoint_auth_method": "none"
}'
```

An operator can instead declare the same client in `SYSTEM_INTEGRATIONS` (entry for `@appstrate/garmin-connect`, auth key `primary`, `token_endpoint_auth_method` set to `none`), which also activates the integration by default. See [Environment Variables](/self-hosting/environment-variables).

The client ID must be the one the refresh token was issued to. Client tiers: [How integrations work](/integrations/how-integrations-work#setting-up-an-integration).

</Step>
<Step>

**Each member.** Garmin's mobile sign-in, MFA included, has no redirect flow, so the member pastes a refresh token instead. The connect form shows a command to run once on the member's own computer. It needs Python with `uv` and uses [python-garminconnect](https://github.com/cyberjunky/python-garminconnect). Garmin rotates the token at each refresh. Paste it as is and do not share it.

</Step>
</Steps>

## Limits of Garmin Connect

- The agent is told to send `GET` requests only, but nothing enforces a method. The token reaches all of `connectapi.garmin.com` and can also edit and delete the owner's activities, settings, workouts and gear.
- A `401` that persists means the member must reconnect. A `429` means Garmin is throttling, and the agent is told to stop.

## Garmin LiveTrack

Nothing to register. The connection is the owner's personal LiveTrack link, of the form `https://livetrack.garmin.com/<name>` or `https://live.garmin.com/<name>`, shown in Garmin Connect or Garmin Messenger. The manifest asks for an active subscription (inReach, Connect+ or Outdoor Maps+) and for sessions visible to everyone. A link protected by a passcode or access code is not supported, and multi-day inReach activities are not read. Use your own link or one its owner gave you.

## Use it in an agent

Excerpt of the agent manifest:

```json
{ "dependencies": { "integrations": { "@appstrate/garmin-connect": "^1.0.0" } } }
```

Example prompt: "List my runs of the last 7 days with distance and average heart rate."
