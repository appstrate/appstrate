# Frontend (`@appstrate/web`)

Conventions for `apps/web` and `packages/ui`. Root guide: `../../AGENTS.md`.

- **i18n**: `i18next` + `react-i18next`. Default `fr`, supported `fr`/`en`. Namespaces `common`/`agents`/`settings`/`chat`/`files`. Locales in `apps/web/src/locales/{lang}/`.
- **Errors**: never print `err.message` — for an `ApiError` it is the server's English `detail`. An inline slot (form error, `<ErrorState>` body) shows `errorMessage(err)`; a toast goes through `toastError(err)` / `onMutationError` (the global mutation toast), the ONE toast format, which adds "Erreur :" only when nothing is translated (all in `lib/mutation-error.ts`). They name the refusal by its `code`: `apiError.<code>` in `locales/{fr,en}/common.json` (`<code>_nofield` when the same code is also emitted without a field), or for a `validation_failed` the first `errors[]` item's code, field and message, plus the count of the others. One sentence per code: a surface keeps a sentence of its own only when it says more than the code can anywhere else (the editor's size limit, "publish before enforcing"), never as a second copy. **Detail rule**: a sentence ends with `{{message}}` when the server's detail carries a value the lead lacks (a name, a count, a path, the permission); it drops it when the detail is a constant restating the lead. A code with no key keeps the server's own text; a failure that says nothing gets `error.generic`. A new server code needs its key in both locales: `lib/test/api-error-codes.test.ts` reads the codes from the API source and from the lists the error classes export, and fails otherwise — and on a key no code matches. Better Auth failures are thrown as coded `ApiError`s by the `use-auth` seam (`toAuthError`). **What is enforced vs convention**: ESLint bans importing `getErrorMessage` in `apps/web/src` (exempt: `lib/mutation-error.ts`); a direct `.message` read is NOT linted — a syntax rule was tried and its 20 hits were all legitimate (comparisons, log entries, react-hook-form field errors, the auth seam) — so that half is review.
- **Styling**: Tailwind 4 (`@tailwindcss/vite` + `tailwind-merge`). Single `styles.css`, `@import "tailwindcss"` + custom `@theme inline` dark theme. Utility classes only.
- **Auth**: Better Auth React client. `credentials: "include"` + `X-Org-Id`/`X-Space-Id` injected by the typed client's middleware (`api/client.ts`) from `org-store`/`space-store`.
- **Realtime**: SSE hooks (`use-realtime.ts`) + `useGlobalRunSync` patches React Query cache directly for `run_update` AND `connection_update` events (the latter drives live `Reconnection required` badge updates across tabs). `useGlobalRunSync` uses `fetch()` + `ReadableStream` (NOT `EventSource`) to avoid Safari auto-reconnect — **do not convert**. `GlobalRealtimeSync` mounted inside `MainLayout` only (not onboarding/welcome). SSE channels emitted: `run_update`, `run_log`, `run_metric`, `connection_update` — actor-scoped server-side via subscriber filter on `userId`/`endUserId`.
- **Feature gating**: `useAppConfig()` reads `window.__APP_CONFIG__` (injected at serve time, computed once by `buildAppConfig()`). Core keys (`googleAuth`, `githubAuth`, `smtp`) statically typed; module keys flow through `[key: string]: boolean`. No API call. Module features default `false` when absent. Sidebar/routes/tabs fully gated.
- **Typed API client** (`api/client.ts`) — REQUIRED for new code: `$api.useQuery("get", "/api/end-users", { params })` / `$api.useMutation(...)` (openapi-react-query) and raw `client.GET(...)` (openapi-fetch), typed against `api/schema.d.ts` generated from the OpenAPI spec (`bun run generate:api`; `verify:api-types` in `check` fails when stale). Middleware injects org/space headers + throws `ApiError` (RFC 9457) on non-2xx — direct `client.X()` calls must try/catch, the `{ error }` branch is never populated. Query keys are `[method, path, init]`: pass the spec-declared `X-Org-Id`/`X-Space-Id` header params explicitly in queries so scope is part of the key; after writes invalidate each path string separately (list and `/{id}` differ). The legacy fetch barrel (`api.ts`) is deleted; an ESLint guard (`eslint.config.mjs`) bans its old import specifiers. Path params keep `@` (and the `/` inside `@scope/name` package ids) literal via the client's `pathSerializer` — Hono regex routes match the raw path. Specifics: list envelopes unwrap via `select: (e) => e.data`; multipart goes through `bodySerializer: () => formData` (never set `Content-Type`); blobs via `parseAs: "blob"`; the SchemaForm uploader lives in `api/uploads.ts`. Module-contributed routes (`/api/billing*`, from `@appstrate/module-ee`) are discovered by `generate:api` like any other, so `use-billing.ts` is typed too. One deliberate raw `fetch` remains — the end-user-realm OAuth token exchange in `src/modules/oidc/lib/oidc.ts`, which must not carry the middleware's platform `X-Org-Id`/`X-Space-Id` headers.
- **React Query keys**: typed-client hooks use `[method, path, init]` (scope rides in init). Run/schedule/package caches keep PINNED legacy keys (`["run", id]`, `["runs", …]`, `["paginated-runs", …]`, `["packages", …]`, `["agents", …]`, `["agent-model"/"agent-proxy", …]`) because `use-global-run-sync` (SSE) and app-switch resets patch/invalidate them by those names — don't re-key without updating the patchers. On org switch, `queryClient.removeQueries` wipes all except `["orgs"]`.
- **Failures are never silent** (`lib/query-client.ts`, `lib/stale-authority.ts`): the mutation cache toasts EVERY failed mutation through `onMutationError` (which translates the refusals it knows) — do not add `onError: onMutationError` to a hook or a `toast.error(getErrorMessage(err))` at a call site, both would say it twice. The only way out is `meta: { errorHandledByCaller: true }`, for a mutation whose callers ALL render the failure differently (a form `setError`, an inline result, a sentence of their own) or a background write the user did not ask for; an `onError` that rolls back or invalidates is not an opt-out. Queries do not retry a 4xx (408/429 excepted). On the typed client, a 401 asks Better Auth whether the session still exists and lands on the login screen when it does not, and a 403/404 re-reads the org + space listings (at most once per 10 s), which is what makes a changed role or a lost space show up without a reload. Raw `fetch` callers are outside this: the SSE streams, and the chat module's own requests (`packages/module-chat/src/ui`) — on `/chat` an expired session is noticed by the shell's typed queries, not by the chat's. A detail page renders an unreadable resource with `<ResourceErrorState error={error} />` (one translated "not found or not accessible" panel for 403/404) — never a silent redirect. In `apps/web`, clipboard writes go through `useCopyToClipboard`, which reports a refused copy (the chat module's own copy button, `packages/module-chat/src/ui/json-view.tsx`, has no toast to report with).
- **Standard components**: `<Modal>` for dialogs (never raw overlays); `<LoadingState>`/`<ErrorState>`/`<EmptyState>` from `page-states.tsx`; `<SchemaForm>` (from `@appstrate/ui/schema-form`) for JSON-Schema forms — file fields are handled inside it via the `uploadClient` upload fn (`api/uploads.ts`), not a separate component.
- **Tests** (`bun test` from `apps/web`; the root `bunfig.toml` preload would start Docker): no DOM. Components render through `test/render.tsx` (`renderToStaticMarkup` + providers, seed `$api.useQuery` keys `[method, path, init]` on a `QueryClient`). Radix portals (`<Modal>`) render nothing there, so a form lives in a body component that returns the `<form>` and the modal owns the chrome. Any code that builds a request body the SPA sends is a pure function under `lib/` with a test that pins the emitted payload — the typed client checks shapes, not values (a client-only sentinel like `"__custom__"` type-checks and still 400s).
- **Rules of React (static gate)**: `apps/web` + `packages/ui` lint with `eslint-plugin-react-hooks` **`recommended-latest`** (`eslint.config.mjs`) — layers the React Compiler static rules (`purity`, `set-state-in-render`/`set-state-in-effect`, `immutability`, `refs`, `static-components`, `preserve-manual-memoization`, …) on top of the core hooks rules. These catch the Rules-of-React violations that cause unnecessary re-renders and fragile components. Enforced in `bun run check` (local + CI lint step) — a static cleanliness/robustness gate, no runtime/Playwright harness. A violation fails the build; fix the component (don't disable the rule).
