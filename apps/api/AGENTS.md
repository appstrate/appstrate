# Backend (`@appstrate/api`)

Conventions for `apps/api`. Root guide: `../../AGENTS.md`. Module authoring: `src/modules/README.md`.

- **Multi-tenant**: DB queries filter by `orgId`, and space-scoped resources (agents, runs, schedules, end-users, api-keys, notifications, packages, files, uploads) additionally by `spaceId`. Org roles are `owner`/`admin`/`member`/`guest`; inside a space the caller holds a space role (preset `admin`/`builder`/`operator`/`viewer`, or an org-defined `space_roles` bundle) resolved from `space_members`. Three documented exceptions: `integration_connections` and `integration_oauth_clients` have `org_id` NOT NULL but a nullable `space_id`, where `space_id IS NULL` is an org-level row serving every space of the org — a connection's tier is its minting client's, and where it binds is the `services/connection-reach.ts` predicate, never a bare `space_id` filter (see `docs/architecture/SPACES.md` → Connections); `webhooks` is polymorphic across levels — see below and `SECURITY.md` → Layer 6.
- **Service layer**: function-based (no classes). `services/state/` (runs, notifications, package-persistence) is the central data-access layer. Drizzle via `import { db } from "@appstrate/db/client"` + schema from `@appstrate/db/schema`.
- **Request pipeline** (`index.ts`): error handler → Request-Id → client-IP (`TRUST_PROXY`) → CORS → bodyLimit → health (`/`) → OpenAPI docs → `/llms.txt` → shutdown gate → `/api/auth/bootstrap` → Better Auth (`/api/auth/*`) → auth middleware (custom strategies → API key `apst_` → cookie → `Appstrate-User`) → **view-as transport guard** (`viewAsTransportGuard`, `lib/view-as.ts` — `X-View-As` is a 400 `view_as_unsupported` on anything but a session or a `deferOrgResolution` token, and the `X-View-As-Active` marker is set on the way out) → **realm guard** (`requirePlatformRealm` — rejects OIDC end-user sessions on platform routes) → org context (`X-Org-Id`) → permission resolution (`resolveViewAs` first: every `permissions` write reads the persona) → space context (`X-Space-Id`, required for space-scoped routes) → API version (`Appstrate-Version`) → `idempotencyGuard()` → route handler (per-route `rateLimit()`/`idempotency()`) → module routers (one per loaded module). The `/api/orgs/:orgId*` family carries the org in the PATH and is exempt from `requireOrgContext`, so `ORG_PATH_MIDDLEWARE` (`middleware/org-path-context.ts` — `apiKeyOrgScopeGuard` then `orgPathContext`) is mounted at `/api/orgs/:orgId/*` ahead of the orgs router AND of every module router, and is where those routes get their org role, ceiling and principal grants.
- **Platform config**: `buildAppConfig()` computed once at boot, serialized as `window.__APP_CONFIG__`, injected into `index.html` at serve time. `googleAuth`/`githubAuth`/`smtp` derived from env presence.
- **External modules**: appended npm specifiers to `MODULES`. Declared-but-not-installed = boot crash.
- **Cost tracking**: `runs.cost` (doublePrecision) = sum of `llm_usage` ledger via `computeRunSpend(runId, orgId)` (`services/state/runs.ts`, single read path). Ingestion paths + precision trade-off: `docs/architecture/RUN_COST.md`.
- **Caching**: one primitive, `createCache` from `@appstrate/core/cache` — read-through `get(key, loader)` with request coalescing, TTL + entry cap, `invalidate`/`clear` broadcast to every replica over Postgres NOTIFY (`lib/cache-bus.ts`, channel `cache_invalidate`, initialised in `lib/boot.ts`). No shared L2 store by design: cached values are single-row reads (a Redis hop costs the same) and some carry decrypted credentials. Never a hand-rolled `Map` with an expiry; never cache a security gate (the oidc SSO flag reads fresh — only the `api_version` pin is cached, `services/org-settings-cache.ts`). Tests: `setCacheClock()` to advance every TTL, `clearAllCachesLocally()` runs in `truncateAll()`.
- **Hono context** (`c.get`): `user`, `orgId`, `orgRole`, `orgSlug`, `orgPermissions`, `scopeCeiling`, `permissions`, `authMethod`, `apiKeyId`, `spaceId`, `space`, `spaceRole`, `viewAs`, `endUser`, `apiVersion`, `package` (set by `requireAgent` — NOT `agent`), `run`, `requestId`, `sessionRealm`.
- **Route guards** (`middleware/guards.ts`): `requireAgent()` (no arg — reads `:scope`/`:name`, loads the package by the PLACEMENT rule `isPackageReadableInSpace` (system ∨ home ∨ a `space_packages` row here), sets `c.set("package")`; mounted by EVERY agent route, and it raises ONE refusal, the opaque `404 agent_not_found` for an agent this space cannot read). `requireActiveAgent()` (the second, narrower question — the EXECUTABLE verdict `agentExecutionBlock` from `lib/package-access.ts`: PLACED here **and** ACTIVE here. `404 agent_not_active_in_space` on the activation half, naming the space and `POST /api/spaces/{id}/packages`; the placement half behind `requireAgent()` can only mean the placement was withdrawn between the two reads, so it answers the opaque `agent_not_found`. Mounted BEHIND `requireAgent()` by the THREE agent execution doors and by nothing else: `POST /api/agents/{scope}/{name}/run` — a rerun is `rerun_from` in that body, not a route — `POST …/schedules` and `GET …/bundle`. `POST /api/runs/remote` is the FOURTH execution door and reads the same verdict inline (`services/registry-run-resolver.ts`), rendering `not_placed` as the byte-identical 404 of a nonexistent id since it takes a package id straight from the caller; the scheduler tick reads it too. It carries a handler marker, `isActiveAgentGate`, so a conformance test reads that list off the Hono route table. Every other agent route is a READ or a per-space CONFIGURE and answers 200 with the switch off — detail, `model`, `proxy`, `persistence`, `runs`, `schedules`, `connection-readiness`, and the writes beside them — carrying the verdict in the payload instead, `AgentDetail.active` — the index carries none, it lists the ACTIVE set; readiness reports it as a blocking error `{ field: "agent", code: "agent_not_active" }`, first in `errors`, with `blocks_run: true`), `requirePackageInOrg()` (package mutation, delegating to `assertPackageMutationAccess` in `lib/package-access.ts`: a package outside the caller's org never loads, so it is a 404, and a system package is a 403; the type's `write`/`delete` permission is then required in the package's **home space** — `packages.home_space_id`, the one authority over a draft and its versions, whatever other space it is placed in. An organization package ALWAYS has one, enforced by the CHECK `packages_org_package_has_home` (drizzle `0067`); the org's DEFAULT space homes the packages that belong to no team, and the only rows with no home are a SYSTEM package (`org_id IS NULL`) and an inline run's `ephemeral` shadow. A caller who cannot even READ the package gets a 404, one who can see it but does not govern it gets a 403. It is the WHOLE authorization of such a route: no `requirePermission(resource, "write")` sits beside it, because a second check against the current space would re-impose the conjunction the home rule replaced — only routes acting on the placement (activate/deactivate/configure/per-space settings) keep one. `PUT /api/packages/{scope}/{name}/home` moves the home, requiring that permission on both ends), `apiKeyOrgScopeGuard()`/`pinnedSpaceScopeGuard()` (stop an API key escaping its org, and any space-pinned credential escaping its space, via path params). RBAC is `requirePermission(resource, action)` (`middleware/require-permission.ts`) — there is **no** `requireAdmin()`/`requireOwner()`/`requireOrgRole()`. `requireSpaceContext()` (`middleware/space-context.ts`) validates `X-Space-Id` (or the API key's own `spaceId`) + space∈org, then resolves the caller's role IN that space and rewrites `permissions` to `ceiling(orgPermissions ∪ spacePermissions)` — 403 `not_a_space_member` (404 for a `private` space) when there is none. Every permission string is org-level OR space-level (`CORE_RESOURCE_LEVELS`, `@appstrate/core/permissions`), so a space-level guard is unsatisfiable on a route that never entered a space; a router outside `SPACE_SCOPED_PREFIXES` that needs one calls the exported `applySpacePermissions(c, space)` (core seam for modules: `enterSpaceContext`). Under API-key auth the principal whose membership is resolved is the key's **creator**, with the key's `scopes` as the ceiling. `docs/architecture/RBAC_PERMISSIONS_SPEC.md` is the reference.
- **One rule per resource, whatever the door**: every REST operation of the MCP module's catalog is also reachable through its `invoke_operation`, dispatched in-process, with every kind of credential: a session, the CLI and MCP instance tokens, the chat's loopback bearers, API keys, third-party OAuth clients, end-user tokens. The catalog leaves out a handful of paths (`isExcludedPath`, `modules/mcp/catalog.ts`); the credential proxy is one, and its own MCP tool, `api_call`, re-enters the same route. A dedicated MCP tool, a chat tool or a route is therefore never a boundary on its own: a refusal placed on one door leaves the same rows open through the next. Before designing access to a resource, read `docs/architecture/RBAC_PERMISSIONS_SPEC.md` §7 (which `principalKind` each credential declares, which one carries a `scopeCeiling` or is bound to one org: an MCP instance token is the `user` principal, not a delegate), list the doors × credentials that reach the resource, and put the rule in the service, computed from the caller, so that every door calls the same function and none restates it. Test it with the chat's loopback token AND a real minted MCP instance token, not only a session. Worked example: the credential proxy, `services/credential-proxy/access.ts` (`authorizeProxyCall` for a run, `reachOutsideRun` outside one), called by the route that both the REST door and `api_call` enter.
- **Model credentials**: who pays a model call is `requestPayerUserId(c)` (`services/model-providers/credential-chain.ts`; `null` = nobody pays with a personal credential), computed once per request at each door and passed down; never derive it again below the door. A run records its payer as `runs.payer_user_id` at launch, and every later door compares against that. The rules (who pays, the chain, what a run keeps) live in `docs/architecture/MODEL_ALIASES.md`, "Who pays".
- **Rate limiting**: Redis-backed `rate-limiter-flexible`. Keyed `method:path:identity` (`userId` / `apikey:{id}`), IP-based for public routes. IETF `RateLimit` headers. Key limits: run 20/min, import 10/min, schedule-create 10/min, run logs 120/min.
- **Docker streams**: multiplexed 8-byte frame headers `[stream_type(1), 0(3), size(4)]` parsed in `streamLogs()`.
- **Package versioning**: semver across `package-versions.ts`, `package-version-deps.ts`, `package-storage.ts`. Tables: `packageVersions`, `packageDistTags`, `packageVersionDependencies`. Enforcement via `@appstrate/core/version-policy` (`validateForwardVersion` — forward-only). Resolution: exact → dist-tag → semver range (`resolveVersionFromCatalog`). Integrity: SHA256 SRI via `@appstrate/core/integrity`.
- **Package types**: `agent`, `skill`, `mcp-server`, `integration`. System tools (`output`/`log`/`note`/`pin`/`publish_file`) are transport-neutral MCP definitions in `packages/core/src/runtime-tool-defs.ts` (served sidecar-side), opt-in per agent via manifest `runtime_tools: string[]` (catalog `@appstrate/core/runtime-tools-catalog`). `output` required only when agent declares `output.schema` (enforced by `agentManifestSchema` superRefine). Outbound third-party API access flows exclusively through **integrations**.
- **System agents**: all agents (system + local) live in DB. System agents loaded from `system-packages/` ZIPs at boot and synced with `orgId: null` (`lib/boot.ts` `syncSystemPackagesToDb()`).
- **Graceful shutdown**: `run-tracker.ts` — stop scheduler → reject new POST → wait in-flight runs (max 30s), and meanwhile the open LLM-proxy streams and their usage rows (`drainProxyMetering`, `services/llm-proxy/metering.ts`) → drain tracked audit inserts (`services/audit.ts` `trackAudit`/`drainAudits`, 5 s cap — the MCP router does not await them on the response path) → modules → DB → exit.
- **Validation (Zod)**: read every JSON body with `readJsonBody(c, schema)` from `@appstrate/core/request-body` — NOT a bare `c.req.json()` + cast, which turns malformed JSON and wrong-shape bodies into 500s. It catches the parse error as a 400 and then runs `parseBody(schema, body)` (`.safeParse()` → throws `invalidRequest()` with RFC-9457 `errors[]`). Pass `{ allowEmpty: true }` only when an empty body genuinely means "no changes". **Body schemas are `.strict()`**: an unknown field is a 400, never a silently dropped value. Naming `{concept}Schema` / `{Concept}` (`z.infer`). JSONB reads use safe narrowing (null/typeof/Array.isArray), not raw `as`. Query params: `z.coerce.number().int().min().max().catch(default).parse()`. **Zod 4** — `z.url()` NOT `z.string().url()`, `z.uuid()`. Reference: `routes/models.ts`, `routes/webhooks.ts`, `routes/organizations.ts`.
- **PUT replaces, PATCH merges** (RFC 9110 §9.3.4, RFC 7396): a `PUT` body is the COMPLETE writable state of its target — every field it sets is required, or its absence has one fixed meaning that does not depend on what is stored (`PUT /api/agents/{scope}/{name}/input-settings`, `PUT /api/billing/managers`, `PUT …/home`). A body whose absent field means "leave it as stored" is a partial update and is served on `PATCH` with merge semantics: absent = unchanged, `null` = clear, and `null` is accepted only on a nullable field. Never serve one shape on both verbs.
- **Optimistic concurrency = `ETag` + `If-Match`** (RFC 9110 §13.1.1), the ONE client-facing mechanism — no version field in a body. `lib/conditional-request.ts`: `setEtag(c, version)` stamps a strong tag minted from the draft's version on the GET and the write's response, `assertIfMatch(c, current, { required? })` answers `412 precondition_failed` (carrying the current `ETag`) on a stale tag and `428 precondition_required` when a mandatory header is absent. The package draft save REQUIRES it and evaluates it inside the draft lock (`mutatePackageDraftFiles`'s `assertVersion`), so check and write are one step; the draft's version is `packages.lock_version`, which never leaves the server. Publish and restore take it optionally. The one server-side form: `PATCH /api/schedules/{id}` judges the patch (actor, connection reach, readiness) against the row it read at the start of the request, then writes it as a compare-and-set on that read's `updated_at` (`updateSchedule`, `services/scheduler.ts` — not a held lock, which PGlite's single connection would deadlock); every write of a schedule's governed state bumps `updated_at` (a fire's `last_run_at`/`next_run_at` bookkeeping does not), so such a write landing in between answers `409 schedule_modified_concurrently` and writes nothing. It also takes the ordinary client-facing form, optionally: `GET`/`POST`/`PATCH` stamp an `ETag` minted from `updated_at`, and a `PATCH` carrying `If-Match` is refused with `412` when the row moved since the client read it (a client that sends none reloads and retries on the 409). A fire disabling its own schedule (`disableScheduleAtFire`) compares the same stamp against the row it read, and leaves a schedule written since as that write stored it. Every other resource is last-write-wins.
- **Validation (AJV)**: `validateAgainstSchema()`/`validateInput()`/`validateOutput()` for **dynamic** manifest schemas only. One AJV instance, `coerceTypes: true`, extra fields allowed.

## Headless Developer Platform

Headless API for embedding agents. Patterns mirror Stripe.

- **Spaces** (`spaces`, prefix `spc_`): each org has a default (`isDefault: true`). API keys scoped to a space. Routes `/api/spaces` (CRUD, admin).
- **End-users** (`end_users`, prefix `eu_`): external users via API, belong to a space. Not Better Auth users. Routes `/api/end-users` (CRUD, admin). Fields: `externalId` (unique/space), `metadata` (JSONB ≤50 keys), `email`, `name`. Default connection profile on creation.
- **`Appstrate-User` header**: impersonation (`eu_` ID). API key auth only — `400` on cookie. Validates end-user belongs to the key's space. Full audit log per impersonation.
- **Webhooks** (`webhooks` prefix `wh_`, `webhook_deliveries`): scoped at **either** level — `spaceId` is nullable and a CHECK ties it to the discriminator, `(level='org' AND space_id IS NULL) OR (level='space' AND space_id IS NOT NULL)` (`packages/db/src/schema/webhooks.ts:66`). `/api/webhooks` is deliberately NOT in `SPACE_SCOPED_PREFIXES` (`middleware/space-context.ts:32`): the module validates an explicit `spaceId` body/query field against the caller's org itself (`assertSpaceBelongsToOrg`, `src/modules/webhooks/routes.ts`) instead of taking `X-Space-Id` from the space-context middleware. Standard Webhooks spec (HMAC-SHA256). BullMQ delivery, 8-attempt backoff — except a DNS miss (final from attempt 3) and the test ping (`test.ping`, one attempt, a real signed delivery). Events: `run.started`/`success`/`failed`/`timeout`/`cancelled`/`connection_missing` (a blocking refusal only: a run that starts without a non-required integration emits none, its launch answers a `warnings[]` item). SSRF protection on URLs. Routes `/api/webhooks` (CRUD + test/ping + rotate + deliveries, admin).
- **Space packages** (`space_packages`): ONE row = the package is PLACED in that space, and its `enabled` (NOT NULL, no DEFAULT — every insert states it) is the space's switch. It also carries the agent's stored input settings (`input_settings` jsonb — `{ values, locked }`, read via `getSpacePackageSettings()`, written only by `PUT /api/agents/{scope}/{name}/input-settings`), the model/proxy overrides, and `shared_by` (who placed it outside its home, `ON DELETE SET NULL`). All of it is per-space (not per-org). **Placed here** = system ∨ `home_space_id` = here ∨ a row here (`placementReadFilter` / `placementRowJoin`, `services/package-placement.ts`); **active here** = the row's `enabled`, or the deployment's default with no row (`source = 'system'`, and for an integration the subset `SYSTEM_INTEGRATIONS` names). `services/package-activation.ts` states the second exactly twice — `activeHereSql()` for the queries (ONE LEFT JOIN, `placementRowJoin(packages.id, spaceId)`) and `isActiveHere(pkg, row)` for the callers holding the rows — and the run gate, the caller-context hints, `AgentDetail.active`, the library's `state` and the type INDEX pages all read those. A row switched off is excluded by every executable reader through that one definition and `agentExecutionBlock`, which is why there is no second "shared but not accepted" table: a placement nobody switched on and one switched off are the same state. Two pages, two questions: an INDEX lists what this space can LAUNCH (the active set), the LIBRARY lists what is PLACED here with its `state` and the switch. **Rights come from spaces**: the role in the placed space decides use (activate, configure, run, schedule), the role in the home decides edit (§6.9 of `docs/architecture/RBAC_PERMISSIONS_SPEC.md`); a placement never grants edit, and co-editing is membership of the home (or `PUT …/home`). Activation is the row's own pair of doors — `POST /api/spaces/{id}/packages` (201 when it switched the package on, 200 when it already was) and `DELETE /api/spaces/{id}/packages/{scope}/{name}` (`enabled = false`, 204, row and settings kept, schedules left armed to fail visibly) — for all four package types, integrations included; `PATCH` carries `modelId`/`proxyId`/`generation_config` and, for a skill, `chat_enforced` (the space imposes its latest published `SKILL.md` on every chat turn — `services/chat-enforced-skills.ts`, cap and budget checked under a per-space advisory lock), and nothing else, on an existing row only. **One door creates a row outside the home: `placePackage`** (`services/space-packages.ts`), behind `POST /api/packages/{scope}/{name}/shares`, the activation door when the caller holds `<type>:share` in the home (`placeAs`), and bundle import. It re-asks share authority on the `packages` row it reads `FOR SHARE`, then refuses `409 share_target_is_home` and `409 package_has_no_version`, and inserts `ON CONFLICT DO NOTHING`; a share lands ON when the sharer may activate in the target, OFF otherwise. Without share authority the activation door outside the home is UPDATE-only (no row → 404). The other creators stay inside the placement rule: `activatePackageWithin` at home or for a system package, `deactivatePackage` for the sticky opt-out of a default-on package, `updateSpacePackage` only where the package is placed without a row and with the default's `enabled` (configuring never activates), and `PATCH /api/integrations/{id}/settings` through `activatePackageWithin`. **One function deletes a row: `withdrawPlacement`** (`services/package-placement.ts`) — it also disables every enabled schedule of the package in that space (`disabled_reason: package_removed`, jobs removed after commit) — called by `revokePackageShare` (`DELETE …/shares/{target}`, home `<type>:share` OR the target's deactivation grant, waived in one's own personal space) and by the `keep: false` branch of `reconcilePlacementsAfterRehome` (the home move). Lock order: `packages` `FOR SHARE` (`loadPlaceablePackage`) then the row `FOR UPDATE`. `package_shares` is read by no application code: `scripts/migration/0048` folds it into rows and the boot guard `assertPackageSharesFolded` refuses to start while it holds one, until the follow-up release drops the table and the guard. A system package is switchable per space like any other, and the scheduler tick re-asks at every fire through the SAME executable predicate the four execution doors use (`agentExecutionBlock`, `lib/package-access.ts` — placed ∧ active, returning `"not_placed" | "not_active" | null` so each caller words its own refusal). `isPackageActiveHere` carries the org boundary in its own query. The row selects no VERSION: outside its home space a package runs its latest published version, and `version=draft` requires `<type>:write` on the package (`403 draft_not_writable`).
- **API versioning**: date-based. Header `Appstrate-Version` (request override + response). Org pinning via `settings.apiVersion`. One supported version today, and it gates no behaviour: no `Deprecation` or `Sunset` header is emitted (preconditions for a second version are in `lib/api-versions.ts`). `middleware/api-version.ts`.
- **Idempotency**: `Idempotency-Key` on POST routes. Redis-backed, 24h TTL, SHA-256 body hash. Keyed to the caller (`idempotencyPrincipal`: auth method, API key id or OAuth client id, actor) — another principal reusing a key is a fresh request. `409` concurrent, `422` body mismatch, `Idempotent-Replayed: true` on cached replay. Only a 2xx is stored: a refusal (4xx) or failure (5xx) releases the key, so a retry is judged again. One route relays the key instead: on `/api/credential-proxy/proxy` it is the upstream's, sent on with the caller's other headers, and the platform de-duplicates nothing (`relayIdempotencyKey`). `middleware/idempotency.ts`.
- **Error handling**: RFC 9457 `application/problem+json` on all endpoints. `ApiError` factories (`invalidRequest`, `unauthorized`, `forbidden`, `notFound`, `conflict`, `gone`, `internalError`, `systemEntityForbidden`). `Request-Id` (`req_`) on all responses.
- **SSE + API key**: SSE endpoints accept `?token=apst_...` query param (EventSource can't send headers). Cookie fallback preserved.

## API Reference

**OpenAPI 3.1 spec is the single source of truth for all API endpoints** (request/response schemas, auth, errors, SSE formats).

- **Source**: `src/openapi/` — modular TS files assembled at build time. Module endpoints contribute via `AppstrateModule.openApiPaths()`.
- **Live spec**: `GET /api/openapi.json` (public). **Docs**: `GET /api/docs` (Swagger UI, public).
- **Validation**: `bun run verify:openapi` — coverage, structural, lint, Zod↔spec bodies, Code ⊆ Spec static analysis. The rule it enforces is "OpenAPI is the source of truth": every code-registered endpoint must be documented and vice versa. (There is no ADR directory in this repo — `scripts/verify-openapi.ts` is the authority.)

When working on routes, consult the corresponding file in `src/openapi/paths/`.
