# Backend (`@appstrate/api`)

Conventions for `apps/api`. Root guide: `../../AGENTS.md`. Module authoring: `src/modules/README.md`.

- **Multi-tenant**: DB queries filter by `orgId`, and space-scoped resources (agents, runs, schedules, end-users, api-keys, notifications, packages, files, uploads) additionally by `spaceId`. Org roles are `owner`/`admin`/`member`/`guest`; inside a space the caller holds a space role (preset `admin`/`builder`/`operator`/`viewer`, or an org-defined `space_roles` bundle) resolved from `space_members`. Two documented exceptions: `integration_connections` has **no** `org_id` column at all (space-scoped + per-actor owner; the org tier is enforced by `assertSpaceInScope` in the service, not by a predicate), and `webhooks` is polymorphic across levels — see below and `SECURITY.md` → Layer 6.
- **Service layer**: function-based (no classes). `services/state/` (runs, notifications, package-persistence) is the central data-access layer. Drizzle via `import { db } from "@appstrate/db/client"` + schema from `@appstrate/db/schema`.
- **Request pipeline** (`index.ts`): error handler → Request-Id → client-IP (`TRUST_PROXY`) → CORS → bodyLimit → health (`/`) → OpenAPI docs → `/llms.txt` → shutdown gate → `/api/auth/bootstrap` → Better Auth (`/api/auth/*`) → auth middleware (custom strategies → API key `apst_` → cookie → `Appstrate-User`) → **view-as transport guard** (`viewAsTransportGuard`, `lib/view-as.ts` — `X-View-As` is a 400 `view_as_unsupported` on anything but a session or a `deferOrgResolution` token, and the `X-View-As-Active` marker is set on the way out) → **realm guard** (`requirePlatformRealm` — rejects OIDC end-user sessions on platform routes) → org context (`X-Org-Id`) → permission resolution (`resolveViewAs` first: every `permissions` write reads the persona) → space context (`X-Space-Id`, required for space-scoped routes) → API version (`Appstrate-Version`) → `idempotencyGuard()` → route handler (per-route `rateLimit()`/`idempotency()`) → module routers (one per loaded module). The `/api/orgs/:orgId*` family carries the org in the PATH and is exempt from `requireOrgContext`, so `ORG_PATH_MIDDLEWARE` (`middleware/org-path-context.ts` — `apiKeyOrgScopeGuard` then `orgPathContext`) is mounted at `/api/orgs/:orgId/*` ahead of the orgs router AND of every module router, and is where those routes get their org role, ceiling and principal grants.
- **Platform config**: `buildAppConfig()` computed once at boot, serialized as `window.__APP_CONFIG__`, injected into `index.html` at serve time. `googleAuth`/`githubAuth`/`smtp` derived from env presence.
- **External modules**: appended npm specifiers to `MODULES`. Declared-but-not-installed = boot crash.
- **Cost tracking**: `runs.cost` (doublePrecision) = sum of `llm_usage` ledger via `computeRunSpend(runId, orgId)` (`services/state/runs.ts`, single read path). Ingestion paths + precision trade-off: `docs/architecture/RUN_COST.md`.
- **Caching**: one primitive, `createCache` from `@appstrate/core/cache` — read-through `get(key, loader)` with request coalescing, TTL + entry cap, `invalidate`/`clear` broadcast to every replica over Postgres NOTIFY (`lib/cache-bus.ts`, channel `cache_invalidate`, initialised in `lib/boot.ts`). No shared L2 store by design: cached values are single-row reads (a Redis hop costs the same) and some carry decrypted credentials. Never a hand-rolled `Map` with an expiry; never cache a security gate (the oidc SSO flag reads fresh — only the `api_version` pin is cached, `services/org-settings-cache.ts`). Tests: `setCacheClock()` to advance every TTL, `clearAllCachesLocally()` runs in `truncateAll()`.
- **Hono context** (`c.get`): `user`, `orgId`, `orgRole`, `orgSlug`, `orgPermissions`, `scopeCeiling`, `permissions`, `authMethod`, `apiKeyId`, `spaceId`, `space`, `spaceRole`, `viewAs`, `endUser`, `apiVersion`, `package` (set by `requireAgent` — NOT `agent`), `run`, `requestId`, `sessionRealm`.
- **Route guards** (`middleware/guards.ts`): `requireAgent()` (no arg — reads `:scope`/`:name`, loads the package by the PLACEMENT rule `isPackageReadableInSpace` (system ∨ home ∨ shared), sets `c.set("package")`; mounted by EVERY agent route, and it raises ONE refusal, the opaque `404 agent_not_found` for an agent this space cannot read). `requireActiveAgent()` (the second, narrower question — the EXECUTABLE verdict `agentExecutionBlock` from `lib/package-access.ts`: PLACED here **and** ACTIVE here. `404 agent_not_active_in_space` on the activation half, naming the space and `POST /api/spaces/{id}/packages`; the placement half behind `requireAgent()` can only mean the placement was revoked between the two reads, so it answers the opaque `agent_not_found`. Mounted BEHIND `requireAgent()` by the THREE agent execution doors and by nothing else: `POST /api/agents/{scope}/{name}/run` — a rerun is `rerun_from` in that body, not a route — `POST …/schedules` and `GET …/bundle`. `POST /api/runs/remote` is the FOURTH execution door and reads the same verdict inline (`services/registry-run-resolver.ts`), rendering `not_placed` as the byte-identical 404 of a nonexistent id since it takes a package id straight from the caller; the scheduler tick reads it too. It carries a handler marker, `isActiveAgentGate`, so a conformance test reads that list off the Hono route table. Every other agent route is a READ or a per-space CONFIGURE and answers 200 with the switch off — detail, `model`, `proxy`, `persistence`, `runs`, `schedules`, `connection-readiness`, and the writes beside them — carrying the verdict in the payload instead, `AgentDetail.active` — the index carries none, it lists the ACTIVE set; readiness reports it as a blocking error `{ field: "agent", code: "agent_not_active" }`, first in `errors`, with `blocks_run: true`), `requireOrgAgent()`, `requirePackageInOrg()` (package mutation, delegating to `assertPackageMutationAccess` in `lib/package-access.ts`: a package outside the caller's org never loads, so it is a 404, and a system package is a 403; the type's `write`/`delete` permission is then required in the package's **home space** — `packages.home_space_id`, the one authority over a draft and its versions, whatever other space it is placed in. An organization package ALWAYS has one, enforced by the CHECK `packages_org_package_has_home` (drizzle `0067`); the org's DEFAULT space homes the packages that belong to no team, and the only rows with no home are a SYSTEM package (`org_id IS NULL`) and an inline run's `ephemeral` shadow. A caller who cannot even READ the package gets a 404, one who can see it but does not govern it gets a 403. It is the WHOLE authorization of such a route: no `requirePermission(resource, "write")` sits beside it, because a second check against the current space would re-impose the conjunction the home rule replaced — only routes acting on the placement (activate/deactivate/configure/per-space settings) keep one. `PUT /api/packages/{scope}/{name}/home` moves the home, requiring that permission on both ends), `requireMutableAgent()` (403 system package, 409 running runs), `apiKeyOrgScopeGuard()`/`pinnedSpaceScopeGuard()` (stop an API key escaping its org, and any space-pinned credential escaping its space, via path params). RBAC is `requirePermission(resource, action)` (`middleware/require-permission.ts`) — there is **no** `requireAdmin()`/`requireOwner()`/`requireOrgRole()`. `requireSpaceContext()` (`middleware/space-context.ts`) validates `X-Space-Id` (or the API key's own `spaceId`) + space∈org, then resolves the caller's role IN that space and rewrites `permissions` to `ceiling(orgPermissions ∪ spacePermissions)` — 403 `not_a_space_member` (404 for a `private` space) when there is none. Every permission string is org-level OR space-level (`CORE_RESOURCE_LEVELS`, `@appstrate/core/permissions`), so a space-level guard is unsatisfiable on a route that never entered a space; a router outside `SPACE_SCOPED_PREFIXES` that needs one calls the exported `applySpacePermissions(c, space)` (core seam for modules: `enterSpaceContext`). Under API-key auth the principal whose membership is resolved is the key's **creator**, with the key's `scopes` as the ceiling. `docs/architecture/RBAC_PERMISSIONS_SPEC.md` is the reference.
- **Rate limiting**: Redis-backed `rate-limiter-flexible`. Keyed `method:path:identity` (`userId` / `apikey:{id}`), IP-based for public routes. IETF `RateLimit` headers. Key limits: run 20/min, import 10/min, schedule-create 10/min, run logs 120/min.
- **Route registration order**: `userAgentsRouter` MUST register before `agentsRouter` in `index.ts` — Hono matches in order.
- **Docker streams**: multiplexed 8-byte frame headers `[stream_type(1), 0(3), size(4)]` parsed in `streamLogs()`.
- **Package versioning**: semver across `package-versions.ts`, `package-version-deps.ts`, `package-storage.ts`. Tables: `packageVersions`, `packageDistTags`, `packageVersionDependencies`. Enforcement via `@appstrate/core/version-policy` (`validateForwardVersion` — forward-only). Resolution: exact → dist-tag → semver range (`resolveVersionFromCatalog`). Integrity: SHA256 SRI via `@appstrate/core/integrity`.
- **Package types**: `agent`, `skill`, `mcp-server`, `integration`. System tools (`output`/`log`/`note`/`pin`/`publish_file`) are transport-neutral MCP definitions in `packages/core/src/runtime-tool-defs.ts` (served sidecar-side), opt-in per agent via manifest `runtime_tools: string[]` (catalog `@appstrate/core/runtime-tools-catalog`). `output` required only when agent declares `output.schema` (enforced by `agentManifestSchema` superRefine). Outbound third-party API access flows exclusively through **integrations**.
- **System agents**: all agents (system + local) live in DB. System agents loaded from `system-packages/` ZIPs at boot and synced with `orgId: null` (`lib/boot.ts` `syncSystemPackagesToDb()`).
- **Graceful shutdown**: `run-tracker.ts` — stop scheduler → reject new POST → wait in-flight (max 30s) → drain tracked audit inserts (`services/audit.ts` `trackAudit`/`drainAudits`, 5 s cap — the MCP router does not await them on the response path) → modules → DB → exit.
- **Validation (Zod)**: read every JSON body with `readJsonBody(c, schema)` from `@appstrate/core/request-body` — NOT a bare `c.req.json()` + cast, which turns malformed JSON and wrong-shape bodies into 500s. It catches the parse error as a 400 and then runs `parseBody(schema, body)` (`.safeParse()` → throws `invalidRequest()` with RFC-9457 `errors[]`). Pass `{ allowEmpty: true }` only when an empty body genuinely means "no changes". **Body schemas are `.strict()`**: an unknown field is a 400, never a silently dropped value. Naming `{concept}Schema` / `{Concept}` (`z.infer`). JSONB reads use safe narrowing (null/typeof/Array.isArray), not raw `as`. Query params: `z.coerce.number().int().min().max().catch(default).parse()`. **Zod 4** — `z.url()` NOT `z.string().url()`, `z.uuid()`. Reference: `routes/models.ts`, `routes/webhooks.ts`, `routes/organizations.ts`.
- **Validation (AJV)**: `validateAgainstSchema()`/`validateInput()`/`validateOutput()` for **dynamic** manifest schemas only. One AJV instance, `coerceTypes: true`, extra fields allowed.

## Headless Developer Platform

Headless API for embedding agents. Patterns mirror Stripe.

- **Spaces** (`spaces`, prefix `spc_`): each org has a default (`isDefault: true`). API keys scoped to a space. Routes `/api/spaces` (CRUD, admin).
- **End-users** (`end_users`, prefix `eu_`): external users via API, belong to a space. Not Better Auth users. Routes `/api/end-users` (CRUD, admin). Fields: `externalId` (unique/space), `metadata` (JSONB ≤50 keys), `email`, `name`. Default connection profile on creation.
- **`Appstrate-User` header**: impersonation (`eu_` ID). API key auth only — `400` on cookie. Validates end-user belongs to the key's space. Full audit log per impersonation.
- **Webhooks** (`webhooks` prefix `wh_`, `webhook_deliveries`): scoped at **either** level — `spaceId` is nullable and a CHECK ties it to the discriminator, `(level='org' AND space_id IS NULL) OR (level='space' AND space_id IS NOT NULL)` (`packages/db/src/schema/webhooks.ts:66`). `/api/webhooks` is deliberately NOT in `SPACE_SCOPED_PREFIXES` (`middleware/space-context.ts:32`): the module validates an explicit `spaceId` body/query field against the caller's org itself (`assertSpaceBelongsToOrg`, `src/modules/webhooks/routes.ts`) instead of taking `X-Space-Id` from the space-context middleware. Standard Webhooks spec (HMAC-SHA256). BullMQ delivery, 8-attempt backoff. Events: `run.started`/`success`/`failed`/`timeout`/`cancelled`. SSRF protection on URLs. Routes `/api/webhooks` (CRUD + test/ping + rotate + deliveries, admin).
- **Space packages** (`space_packages`): one row per (package, space placed), carrying the agent's stored input settings (`input_settings` jsonb — `{ values, locked }`, read via `getSpacePackageSettings()`, written only by `PUT /api/agents/{scope}/{name}/input-settings`), the model/proxy overrides and `enabled`. All of it is per-space (not per-org). Activation is the row's own pair of doors — `POST /api/spaces/{id}/packages` (upsert, `enabled = true`, 201 when it switched the package on and 200 when it already was) and `DELETE /api/spaces/{id}/packages/{scope}/{name}` (`enabled = false`, 204) — for all four package types, integrations included; `PUT` carries `modelId`/`proxyId`/`generationConfig` and nothing else. A DEACTIVATION never deletes the row: the space keeps its settings. Two acts drop it — revoking the share that placed the package, and a home move that releases the space it left (`keep_in_previous_home: false`). The run gate asks ONE question — is the package ACTIVE here — and the ROW ALWAYS WINS **where the package is PLACED**: the row's `enabled` when the space holds one and the package is homed or shared here, the deployment's default when there is no row (`source = 'system'`, and for an integration the subset `SYSTEM_INTEGRATIONS` names). `services/package-activation.ts` states it exactly twice — `activeHereSql(spaceId)` for the queries, which conjoins `placementReadFilter` and expects BOTH LEFT JOINs (`space_packages` and `package_shares`, each on (package, this space)), and `isActiveHere(pkg, row, placed)` for the callers holding the rows — and the run gate, the caller-context hints, `AgentDetail.active`, the library's `state`, the type INDEX pages and the space's own package reads all read those. Two pages, two questions: an INDEX lists what this space can LAUNCH (the active set, nothing else), the LIBRARY lists what is PLACED here with its `state` and the switch that changes it. An ORPHAN row (no home, no share) is therefore active NOWHERE, and no live code path creates one — `scripts/migration/0016` repairs the inherited ones. `isPackageActiveHere` carries the org boundary in its own query. A system package is switchable per space like any other, and the scheduler tick re-asks at every fire through the SAME executable predicate the four execution doors use (`agentExecutionBlock`, `lib/package-access.ts` — placed ∧ active, returning `"not_placed" | "not_active" | null` so each caller words its own refusal): a deactivated or unplaced agent produces a visible failed run naming which of the two it was, and the schedule stays armed. The three doors (`activatePackageWithin`, `deactivatePackage`, `updateSpacePackage`) are the only writers that CREATE a `space_packages` row; the row is deleted by `revokePackageShare` and by the `keep: false` branch of `reconcilePlacementsAfterRehome`, and `setBlockUserConnections` updates one column in place on a row already placed; `PATCH /api/integrations/{id}/settings` materialises its row through the activation door rather than inserting one itself, and `updateSpacePackage` refuses to create a row for a package merely OFFERED here, since a row means active. `package_shares` has three writers as well: `services/package-shares.ts` (the offer route), the activation door when it has to create the offer it takes up, and `services/package-placement.ts` → `reconcilePlacementsAfterRehome`, the ONE reconciliation shared by the home move and the personal-space sweeper. The row selects no VERSION: outside its home space a package runs its latest published version, and `version=draft` requires `<type>:write` on the package (`403 draft_not_writable`).
- **API versioning**: date-based. Header `Appstrate-Version` (request override + response). Org pinning via `settings.apiVersion`. `Sunset` header on deprecated. `middleware/api-version.ts`.
- **Idempotency**: `Idempotency-Key` on POST routes. Redis-backed, 24h TTL, SHA-256 body hash. `409` concurrent, `422` body mismatch, `Idempotent-Replayed: true` on cached replay. `middleware/idempotency.ts`.
- **Error handling**: RFC 9457 `application/problem+json` on all endpoints. `ApiError` factories (`invalidRequest`, `unauthorized`, `forbidden`, `notFound`, `conflict`, `gone`, `internalError`, `systemEntityForbidden`). `Request-Id` (`req_`) on all responses.
- **SSE + API key**: SSE endpoints accept `?token=apst_...` query param (EventSource can't send headers). Cookie fallback preserved.

## API Reference

**OpenAPI 3.1 spec is the single source of truth for all API endpoints** (request/response schemas, auth, errors, SSE formats).

- **Source**: `src/openapi/` — modular TS files assembled at build time. Module endpoints contribute via `AppstrateModule.openApiPaths()`.
- **Live spec**: `GET /api/openapi.json` (public). **Docs**: `GET /api/docs` (Swagger UI, public).
- **Validation**: `bun run verify:openapi` — coverage, structural, lint, Zod↔spec bodies, Code ⊆ Spec static analysis. The rule it enforces is "OpenAPI is the source of truth": every code-registered endpoint must be documented and vice versa. (There is no ADR directory in this repo — `scripts/verify-openapi.ts` is the authority.)

When working on routes, consult the corresponding file in `src/openapi/paths/`.
